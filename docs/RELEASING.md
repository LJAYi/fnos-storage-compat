# 0.1 发布与维护

0.1.0 只发布既有 OMV 8/Basic/ext4 能力。后续 0.1.x 限于缺陷、安全、构建及
文档修复；不新增兼容性。项目版本与上游内核、mdadm 版本分别记录。

首版分发形式：Git 仓库 + 离线二进制集合 + 对应源码材料。
不搭建自动更新服务或签名 APT 仓库；这些不属于 0.1 工作范围。

发布门槛：

1. 范围/样本来源记录完整；入口包无站点数据、维护脚本和额外服务。
2. 保留既有 clean install、upgrade、rollback、migration 验收证据。
3. 完成真实卸载/重装、限量持续 I/O、可丢弃样本客体异常停机恢复测试。
4. 检查最终文件及源码 SHA256、包清单、源码/许可证对应关系。
5. 发布目录扫描凭据、私钥、主机地址、真实磁盘标识及站点配置；不得发布工作盘。
6. 确认发布仓库，使用不可变 tag 和 Release；修复用新版本，不覆盖已发布资产。

相同候选二进制通过验证后晋升，不为发布标签无故重新编译内核。
入口包从 rc3 升到 0.1.0 只更新发布描述和文档，精确依赖不变。

内核安全或功能缺陷修复需要独立 kernelrelease、包版本及完整回归；不得覆盖
正在运行的模块树。文档/入口修复不要求重编内核。优先采用满足功能且通过
测试的发行版官方内核/工具，避免无必要地长期维护自定义分支。

更新需维护窗口和人工重启；不自动更改磁盘、导入 OMV 或切换业务共享。
暂不承诺商业 SLA。收到可复现 bug 后在已支持矩阵内定位、补回归并发补丁版。

公开问题报告只附脱敏信息；不要公开口令、密钥、完整 OMV 配置或用户数据。
